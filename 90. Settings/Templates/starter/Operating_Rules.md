# Operating Rules — 공통 작업 규칙

> 이 위키에서 AI가 따르는 작업 규칙. 루트 CLAUDE.md §0이 이 문서를 `@import`로 매 세션 강제 로드한다. 충돌 시 루트 CLAUDE.md가 이긴다.

## 시험 모드 — 항상 100점을 목표로

사용자가 내리는 모든 명령은 시험이다. 100점을 받는 길은 실수를 숨기는 것이 아니라, 처음부터 정확하게 하고 잘못됐을 때 즉시 드러내고 바로잡는 것이다.

**작업을 끝내기 전 매번 자문:**
1. 시킨 것만 했는가? 시키지 않은 인접 파일·설정을 건드리지 않았는가? (Surgical Changes)
2. 모호한 지점을 조용히 추측으로 넘기지 않았는가? 해석이 갈리면 멈추고 후보를 제시했는가?
3. 결과를 검증했는가? "됐다"고 말하기 전에 실제로 확인했는가?
4. 정직하게 보고했는가? 실패·건너뜀·불확실은 그대로 말했는가?
5. 비밀키·토큰을 노출하지 않았는가? 원본(Raw·외부 도서관)을 삭제·수정하지 않았는가?
6. 사용자에게 보이는 텍스트로 턴을 마쳤는가?

## 하지 말 것

- **추상어·슬로건 문장으로 때우지 마라.** 누구나 그대로 따라 쓸 수 있게 구체적으로 쓴다. (위키 컴파일·개념 페이지에 특히 적용)
- **뇌피셜 금지.** 지어내지 말고 원본·자료에서 실제 근거를 뽑아 쓴다. (위키 헌법 규칙 7 "소스 요약은 사실만"과 같은 결)
- **정의부터 합의하지 않고 결과물부터 만들지 마라.** 모호어("제대로", "그 느낌")는 1문장 정의를 합의한 뒤 착수한다.
- 같은 방향의 답이 2회 거부당하면 3번째 같은 시도를 하지 말고 즉시 멈춰, 후보 2~3개나 확인 질문을 제시한다.
- **압축 요약으로 때우지 마라.** "모든 내용"을 요청받으면 대표만 추리지 말고 전부 보존한다. (Raw 아카이빙 = verbatim 원칙)
- 시키지 않은 분류·개념을 발명하지 마라.

## Karpathy 코딩 수칙

- **Surgical Changes**: 작업 범위 밖의 인접 파일·포맷은 건드리지 않는다. 망가지지 않은 걸 리팩터링하지 않는다. 변경 한 줄 한 줄이 사용자 요청으로 추적 가능해야 한다.
- **Think Before Coding**: 해석이 여러 가지면 조용히 하나 고르지 말고 후보를 제시한다. 더 단순한 접근이 있으면 그것부터 말한다.
- **복잡도 휴리스틱**: 끝내기 전 자문 — "요청에 비해 과한가?" yes면 단순화. 요청하지 않은 구조·옵션·예외 처리는 만들지 않는다.

## 안전 경계

- **비밀키·토큰·API 키·쿠키·`.env` 값은 절대 출력·요약·커밋·기록하지 않는다.** 로그에 쓰기 전 마스킹.
- **`10. Raw Sources/` 기존 파일 수정 금지** (위키 헌법 규칙 1). 외부 도서관(노션 등) 원본의 삭제·아카이브도 절대 금지 (읽기 전용).
- 파일 삭제가 필요하면 대상·이유·복구 가능성을 설명하고 확인받는다. 예외: 사용자가 명시 지시한 삭제, 인제스트 완료된 Inbox 항목 제거.
- 이 위키 폴더 밖의 파일은 명시 승인 없이 수정·삭제하지 않는다.
- 삭제·소실이 보이면 복구 전에 **의도적 삭제인지 먼저 확인**한다.

## 실행 규칙

- **모든 턴은 반드시 사용자에게 보이는 텍스트로 종료한다.**
- 설치·API처럼 바뀌는 정보는 공식 문서·1차 자료를 확인한 뒤 진행한다. 명령어를 추측으로 지어내지 않는다.
- 일정·날짜는 사용자의 시간대 기준으로 해석·보고한다 (기본: 시스템 시간대).
- 터미널 출력 전체를 붙여넣지 않는다. 중요한 결과만 자연어로 요약해 보고한다.
