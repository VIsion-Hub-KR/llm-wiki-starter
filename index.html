LLM WIKI 스타터 킷

명령 세 줄이면
나만의 LLM Wiki가 세팅됩니다.

AI가 유지·관리하는 지식 위키 — 설치 인터뷰가 당신이 일을 나누는 방식을 묻고, 그 좌표계로 위키의 계층 구조를 만듭니다. 기성복 템플릿이 아니라 맞춤복입니다.

15–20분 무료 Claude Code 내 컴퓨터에서 실행

1킷 받기

위키가 살 폴더 위치까지 한 줄에 들어 있습니다. 경로(~/Documents/LLM-Wiki)는 원하는 대로 바꿔도 됩니다 — 명령 세 줄 중 첫 줄입니다.

git clone https://github.com/VIsion-Hub-KR/llm-wiki-starter.git ~/Documents/LLM-Wiki

git이 없다면: ZIP 다운로드 후 원하는 위치에 압축 해제. 킷 내용물은 GitHub에서 전부 열람 가능합니다.

2실행

폴더에 들어가 Claude Code를 켜고 한 마디 — 여기까지가 명령 세 줄의 전부입니다:

cd ~/Documents/LLM-Wiki && claude 설치해줘 # 또는: /setup
01
정체성 인터뷰
02
좌표 — 일을 나누는 방식
03
용도·발행 채널
04
소스 습관
05
운영·백업
06
위키 생성 + 첫 인제스트

기존 노션·옵시디언 시스템이 있다면 인터뷰가 그것을 판독해 좌표를 뽑아냅니다. 끝나면 Obsidian으로 폴더를 열어(Open folder as vault) 완성된 위키를 확인하세요.

설치 후엔 세 문장이면 됩니다

이거 위키에 넣어줘 # 인제스트 위키에서 OO 찾아줘 # 질의 위키 건강 점검해줘 # 린트

자주 묻는 질문

옵시디언을 써본 적이 없어요.

괜찮습니다. 옵시디언은 "폴더 속 마크다운 파일을 예쁘게 보여주는 뷰어"로만 쓰면 됩니다. 정리·연결·목차 관리는 전부 AI가 합니다.

이미 노션·에버노트에 자료가 많아요.

그 도구는 "원본 도서관"으로 계속 쓰고, 이 위키는 그중 중요한 것만 소화하는 층으로 두면 됩니다. 설치 인터뷰에서 알려주시면 기존 시스템을 판독해 당신의 좌표계를 뽑는 데도 씁니다.

자료를 다 옮겨야 하나요?

아니요. 전부 옮기는 순간 위키는 저품질 복사본이 됩니다. "왜 수집했는지" 답할 수 있는 것만 넣는 게 이 시스템의 핵심 규칙(Gold In Gold Out)입니다.

왜 폴더 분류가 아니라 '좌표'인가요?

지식은 보통 여러 영역에 걸칩니다. 폴더는 한 곳만 허락하지만, 좌표(태그)와 워크스테이션 맵은 여러 영역에서 같은 지식을 재사용하게 해줍니다. 나중에 역할·팀이 늘어도 폴더 재편 없이 좌표 한 줄만 추가하면 됩니다.
